## 已实施的修订

**P3 收紧缺失信息的含义。** 只列阻碍理解指代或明确请求的必要信息，不枚举假设的部门、公司名称、费用类型、制度版本作为必填条件。主题已明确时保留知识问题意图，让主模型先查资料。历史助手的业务结论不能填入已确认上下文。

**P4 强化实际动作与证据规则。** 对能识别主题的制度/产品问题先真实检索；首次 Query 保留原问题，改写可放第二项；不得在没有工具观察时声称已经搜索或没有资料。发现两份原文冲突后实际补查适用范围、替代关系或裁决公告。原文足以支持且未发现冲突时据原文回答，避免因假设性缺失条件过度拒答。工具持续读取失败返回 `tool_error`，不复述未核实摘要数字。日期、标题和“主文件”称呼不构成优先级。

**P5 保留修复边界。** 校验提示必要原文读取失败时，修复应准确返回工具错误，删除未读取摘要中的数值；不能伪称完成补检索，不能在修复阶段新增工具动作。

**新增轨迹一致性校验。** [provenance.py](../../src/provenance.py) 只看真实工具观察：没有成功搜索时拒绝 `insufficient_evidence`；读取失败且没有成功读取时拒绝用资料不足掩盖故障；显式声明文档冲突时检查至少两份成功读取及随后的补检索尝试。它不读取用例答案、不自动判语义冲突，也不能识别所有虚构决策摘要或别的原因码，因此仍须模型和人工判断。

**修正 C09 的证据标注。** 在 [cases.json](../../data/cases.json) 增加 `acceptable_evidence_sets`：D01 或 D02 任一充分的已读来源均可支持 30 天答案；完整 `required_evidence` 仍含双方用于覆盖率统计。如果答案声称两份规则一致，则仍需查证双方。检查条件调整不认可首轮错误的版本或权威性理由，也不将旧汇总回写为通过。

P1/P2/P6 未修改，P3/P4/P5 及用例文件的现行哈希登记在 [manifest v3](../../data/manifest.json)。v2 为首轮失败后的修订阶段，v3 继续纳入第二轮复核后的约束。原稿和旧运行目录保留；[validation.json](../../data/validation.json) 是首版静态检查历史，不覆盖为新提示词版本的成功记录。

## 用户的实际参与及复验状态

用户对本次失败修正明确回复：**“认可这一修正：先检索，有证据就回答”。** 这项意见已记录到 [04-ai-usage.md](../04-ai-usage.md)。该认可不扩展为所有合成资料、P3—P5 全部措辞、C09 标注调整、最终模型选择或全部结果已通过个人验收；其余节点继续待审阅。

修订后已运行 [acceptance-single-02](../../examples/real/acceptance-single-02/summary.json)，自动初筛为 10/10（仍包含 C10 Mock），但执行 Agent 对照 Trace 发现新的遗漏：C02 的补检索返回参数错误，旧检查仅因存在搜索调用就误判已经查证；C07 虽返回 `tool_error`，仍复述未读取的搜索摘要数字；C05 首轮查询未逐字保留原问题。因此不能将该轮自动结果表述为全部验收通过。

v3 已将补检索成功观察纳入正常 C02 的验收判定；工具层保留首次有效检索的原问题，同时记录模型原请求与实际执行查询；没有已读原文且模型选择工具失败时，保留模型原提案并呈现基于实际错误的说明。实现细节见 [02-solution.md](../02-solution.md)。同条件 single/split 重复比较已经启动，最终效果以评估文档为准，不预写成功。

由于这些修改使用了验收失败作为反馈，后续属于回归验证，不作为完全未见测试成绩。所有旧输出与检查结果保持可追溯；自动检查的漏判也作为真实失败保留。
