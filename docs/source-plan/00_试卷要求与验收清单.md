# 小影校招 AI Agent 开发岗：笔试要求清单

整理日期：2026-10-31。来源：用户在本会话提供的《试卷说明》全文。

当前阶段：已选第3题“企业知识问答 Agent”，已收到该题正文与验收点。当前只编写技术方案和提示词，由另一位执行Agent后续实现；尚未实现或运行验证。执行入口见[01方案与执行交接](01_企业知识问答Agent_方案与执行交接.md)。所有完成状态须依据实际代码、运行记录和测试结果更新。

## 1. 核心关键词

**业务理解｜可运行项目｜模型驱动决策｜Agent Loop / ReAct｜工具执行与观察回传｜动态调整｜执行上限｜可复现运行｜实际 Trace｜测试覆盖｜AI 使用披露｜个人贡献｜学习改进｜GitHub 最终 commit**

考核主线：理解业务问题 → 完成核心链路 → 用测试和运行记录证明效果 → 解释技术取舍、本人修改和改进过程。

## 2. 必须遵守的通用要求

| 编号 | 要求 | 后续核对依据 |
|---|---|---|
| R01 | 从四道项目题中任选一道 | 明确题号，列出该题全部验收点 |
| R02 | 交付可运行代码 | CLI、HTTP API、Notebook 三选一，给出可复制的运行命令或执行步骤；截图、视频不能替代代码 |
| R03 | 实现模型驱动的决策循环 | 至少一次“模型选择动作 → 执行工具 → 观察结果 → 模型调整下一步或结束” |
| R04 | 证明动态决策 | 至少两条实际执行路径，体现模型根据不同工具结果调整动作 |
| R05 | 设置执行边界 | 设置执行步数或工具调用次数上限，达到上限返回明确的未完成状态 |
| R06 | Trace 字段完整 | 记录步骤、工具参数、返回摘要、后续动作、简要决策依据；无须提交模型内部思维过程 |
| R07 | 覆盖三类场景 | 至少三组输入、实际输出及运行记录，覆盖正常、信息或资料不足、工具失败 |
| R08 | 覆盖所选题全部验收点 | 同一用例可覆盖多个验收点；通用的三类场景之外，仍须补齐题目专属要求 |
| R09 | 提交可执行测试和证据 | `tests/` 保存可执行测试；Trace 与测试结果放在 `examples/`；评估文档引用对应文件 |
| R10 | 文档与实际一致 | 说明需求、设计取舍、预期与实际结果、失败和限制，记录实际用时及未完成部分 |
| R11 | 如实披露 AI 协作 | 记录 AI 使用范围、个人贡献、个人修改及验证结果 |
| R12 | 同一仓库提交全部材料 | 提交题号、GitHub URL、最终 commit SHA；私有仓库须让指定评审账号可读 |
| R13 | 不提交敏感内容 | 仓库中不得提交真实密钥或隐私数据；提供 `.env.example`，无变量时注明无需配置 |
| R14 | 框架使用可解释 | 若采用框架，注明版本、使用的功能及其职责；能说明选择理由和修改结果 |
| R15 | 模型不可用时可离线运行 | 提供离线 Mock 入口并标明边界；Mock 只验证流程，不证明真实模型决策效果 |

## 3. Agent 决策：必须保留的判定边界

允许使用预设流程作为执行骨架，但实际的动作选择与后续调整必须包含模型参与。

以下内容单独存在，不能证明完成 ReAct 决策要求：

- 固定条件分支。
- 自动重试。
- 预先编好的决策日志。

核对每条动态路径时，要能从实际记录看出：模型选择了哪个动作及参数、工具实际返回了什么、该结果如何影响模型下一步或结束决定。

简要决策依据用于说明动作与观察的关系，无须记录模型内部思维过程。具体步数上限尚未选定，不能把自行选择的数值当成试卷原文要求。

## 4. 两类记录要求要同时满足

| 要求 | 数量下限 | 要证明什么 |
|---|---:|---|
| 动态执行路径 | 2 条 | 不同工具返回结果会影响模型的后续动作或结束决定 |
| 场景用例 | 3 组 | 覆盖正常、信息或资料不足、工具失败；每组含输入、实际输出和运行记录 |

两类要求可以复用同一批用例，并非必须分别提交两组加三组、共五组用例。三组用例是否足够，最终还取决于所选题的全部验收点能否被覆盖。

以下仅是后续用例登记框架，尚无实际结果：

| 用例类型 | 应观察的内容 | 当前状态 |
|---|---|---|
| 正常 | 核心业务链路与最终输出；模型如何使用工具结果 | 待选题后设计并执行 |
| 信息或资料不足 | 模型如何根据不足的结果调整下一步或结束 | 待选题后设计并执行 |
| 工具失败 | 失败返回是否进入模型观察，模型随后选择什么动作 | 待选题后设计并执行 |
| 达到执行上限 | 是否停止执行，并返回明确未完成状态；可与其他用例复用 | 待验证 |

## 5. 自由选择、建议与非必需项

| 项目 | 试卷规定 |
|---|---|
| 投入时间 | 建议 3 小时，优先核心链路；须记录实际用时和未完成部分。此说明未给出提交截止日期 |
| 语言、模型、框架 | 自选；可用 Google ADK、AgentScope、LangGraph 等，也可原生实现 |
| 框架价值 | 框架名称不加分；能解释取舍与修改结果才有价值，无须重写框架本身 |
| 业务工具 | 可以是本地函数或 Mock |
| 模型 Mock | 模型不可用时提供离线入口；须明确其不能证明真实模型决策效果 |
| 非必需内容 | 界面、线上部署、多 Agent、生产级 Runtime |
| 文档篇幅 | 不设篇幅要求，重点是准确说明需求、取舍、结果与限制 |

tests/                    可执行测试
examples/                 输入、实际输出、Trace、测试结果

docs/
  01-requirements.md       用户、目标、范围和成功标准
  02-solution.md           调用流程、动态决策、技术取舍
  03-evaluation.md         测试预期、实际结果、失败和限制；引用 examples/ 证据

## 8. 已选题：第3题，企业知识问答 Agent

用户与目标：帮助员工找到制度或产品问题的可靠答案。

输入：问题、可选对话历史；知识材料为带文档ID和版本日期的合成FAQ或制度。必须提供文档检索、片段读取两个工具。

输出：回答、引用文档ID与原文片段、资料缺口、任务状态。

动态决策：模型根据检索结果选择补充检索、读取原文、追问或停止。资料冲突时说明冲突并查证，不能凭空选一个答案。

| 必须验收 | 关键检查 |
|---|---|
| 明确答案 | 引用原文确实支持回答 |
| 文档冲突 | 查证并说明冲突；无裁决依据时请求确认 |
| 资料外问题 | 明确资料缺口，不靠常识补造公司规则 |
| 改写后的相似问题 | 不同表述能定位同一知识，结论保持一致 |
| 上下文追问 | 用已有历史消解指代，保留适用范围 |
| 工具失败 | 失败返回进入观察，后续动作和状态可解释 |

题目给定实例：D01规定报销期限30天，D02规定15天，未说明适用范围与优先级。询问“报销期限多久”时，应列出冲突与引用，并请求确认适用制度；不能擅自回答15天。只检索到D01且无冲突时，可依据D01回答。

审核还会替换文档内容，核对答案和动作是否改变。高分依据是检索改进和冲突处理；无依据回答或错误引用属于关键缺陷。
